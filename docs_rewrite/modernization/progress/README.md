## Known issues found on the way (not fixed)

- rend2 (`codemp/rd-rend2/G2_misc.cpp`) does not compile with llvm-mingw clang 23 (`typedef 'shader_t' cannot be referenced with the 'struct' specifier`, a `CTraceSurface` constructor), already on the commits before the math work; the owner's builds do not use rend2.

- LLVM libc on 32-bit x86 with GCC, Clang 14 and MSVC: its square root falls back to software (`asinf`, `acosf`, `acos`, `rsqrtf` 70 to 300 ns), the same bits; 32-bit is not a target ([../surveys/deterministic-math.md](../surveys/deterministic-math.md) section 10).

- `PM_irand_timesync`'s numbers come from the command's time, which the client chooses within what the server accepts: a modified client could pick times giving favourable saber draws, as with 1.01 and with Source's per-command seed ([../surveys/random-numbers.md](../surveys/random-numbers.md) section 6).

- Upstream OpenJK: the UCRT's `strtof` and `sscanf %f` read a decimal exactly halfway between two floats differently from glibc (`16777217`); fixed on this branch by the entry point's parser.

- Upstream OpenJK: the Linux `Sys_Milliseconds` (`shared/sys/sys_unix.cpp`) reads `gettimeofday`, the wall clock: a step of the system time stops the server's frames (clock going back) or runs up to 5 s of them at once (going forward). Fixed on this branch on 12 November 2026 (`clock_gettime( CLOCK_MONOTONIC )`; [../CHANGES.md](../CHANGES.md) section 23).

- Upstream OpenJK and its forks (TaystJK checked): `Sys_SnapVector` rounds ties away from zero with MSVC and to even elsewhere (prediction misses of up to 2.7 units between a Windows client and a Linux server), and `SnapVector` truncates except with MSVC x86. Fixed on this branch; the code of 1.01, OpenJK and the fix compared side by side, with compatibility and test results, for a merge request upstream: [step-06-cpp-codec.md](step-06-cpp-codec.md), part F, "Code comparison".

- Legacy client (`CL_ParseSnapshot`, `codemp/client/cl_parse.cpp`): when the old snapshot had no vehicle, the server deltas the vehicle player state from nothing (`MSG_WriteDeltaPlayerstate(msg, NULL, &frame->vps, qtrue)`) but the client deltas it from `old->vps`. Seen while writing the legacy benchmark; not tested (the benchmark follows the server and the client as written and found no failure on the recordings).


- The `user*` mod fields are networked 1 bit wide, floats included: only the lowest bit reaches the client unless a mod widens them with the overrides files ([../study/02-engine-code-findings.md](../study/02-engine-code-findings.md) section 2.2).

- With `sv_ratePolicy 2` and `sv_maxRate 0`, the client rate became 0 and `SV_RateMsec` divided by zero (read only, not tested). Gone on this branch since step 11 removed the rate policies; upstream OpenJK still has it.
